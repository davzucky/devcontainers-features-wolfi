# AGENTS.md

Guidance for agentic coding agents working in this repo.

## Scope and goals
- This repo ships DevContainer features for Wolfi base images.
- Each feature is self-contained: metadata, installer, docs, and tests.
- Prioritize compatibility with `chainguard/wolfi-base:latest`.

## Repo layout
- `src/<feature>/devcontainer-feature.json`: feature metadata/options.
- `src/<feature>/install.sh`: feature install script (runs during build).
- `src/<feature>/README.md`: auto-generated feature doc.
- `src/<feature>/NOTES.md`: optional manual notes merged into README.
- `test/<feature>/scenarios.json`: scenario matrix.
- `test/<feature>/<scenario>.sh`: scenario test scripts.

## Build / validate / test
### Tooling
- DevContainer CLI is required: `npm install -g @devcontainers/cli`.
- There is no dedicated build/lint system; tests and validation are via CLI.

### Validate metadata
- Validate all features: `devcontainer validate --base-path-to-features ./src`.

### Run all tests
- Run all features with scenarios: `devcontainer features test .`.
- Run only global scenarios: `devcontainer features test --global-scenarios-only .`.

### Run tests for a single feature
- Run all tests for one feature: `devcontainer features test -f <feature> .`.
- Run only scenarios (skip autogenerated and duplicate tests):
  `devcontainer features test -f <feature> --skip-autogenerated --skip-duplicated .`.

### Run a single scenario test
- Filter by scenario name (matches `scenarios.json` keys):
  `devcontainer features test -f <feature> --filter <scenario-name> .`.
- Example: `devcontainer features test -f node --filter with_yarn .`.

### Run against a specific base image
- `devcontainer features test -f <feature> -i chainguard/wolfi-base:latest .`.

### CI coverage
- When adding a new feature, include it in `.github/workflows/test.yaml` under the `test-scenarios` matrix.

## Code style and conventions
### Shell scripts (`install.sh`)
- Use `#!/bin/sh` and `set -e`.
- Avoid bash-specific features; aim for POSIX sh.
- Use `apk update` before installs.
- Install with `apk add --no-cache`.
- Use env defaults: `VAR=${ENVVAR:-"default"}`.
- Quote variables and paths: `"${VAR}"`.
- Emit helpful `echo` status lines for debugging.
- Validate versions/options and `exit 1` on unsupported values.
- Prefer helper functions like `install_if_not` for idempotence.
- Use ASCII-only comments/strings unless the file already uses Unicode.

### JSON (`devcontainer-feature.json`, `scenarios.json`)
- Use 4-space indentation, no trailing commas.
- Options are camelCase; booleans are `true`/`false`.
- Option names become env vars via uppercasing and sanitization.
- Use `automatic`/`auto` values for auto-detection where applicable.
- Keep scenario names descriptive and aligned with test scripts.

### Docs
- `src/<feature>/README.md` is auto-generated; add extra notes in `NOTES.md`.
- Avoid manual edits to auto-generated sections.

## Naming conventions
- Feature folder name matches feature id (kebab-case).
- Shell variables are UPPER_SNAKE_CASE.
- Test names in `check` should be short, descriptive phrases.

## Error handling and safety
- Fail fast with clear messages and `exit 1` when required.
- Validate required binaries after install using `command -v` checks.
- Prefer idempotent operations (safe to re-run).
- Do not silently ignore unsupported versions or options.

## Feature-specific notes
- All features use `apk` and target Wolfi/Alpine packages.

## Agent workflow tips
- Read existing feature scripts/tests before adding new options.
- Update tests and scenarios whenever options change.
- Keep test coverage for both enabled/disabled optional tooling.
- Use ASCII characters unless the file already uses Unicode.
