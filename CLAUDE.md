## Project Overview

This repository contains DevContainer features designed to work with Wolfi base images - a distroless container base that provides enhanced security and minimal attack surface. The project enables development teams to use DevContainers with Wolfi instead of traditional Debian-based images.

## Repository Structure

```
src/
├── bash/                    # Bash installation feature
├── docker-outside-of-docker/# Docker CLI with host socket access
├── python/                  # Python installation with optional tools
└── user/                   # User creation and configuration
test/                       # Test scenarios for each feature
├── bash/
├── docker-outside-of-docker/
├── python/
└── user/
```

Each feature follows the DevContainer feature specification with:
- `devcontainer-feature.json` - Feature metadata and options
- `install.sh` - Installation script executed during container build
- `README.md` - Feature documentation

## Development Commands

### Testing Features
```bash
# Test all features with scenarios
devcontainer features test .

# Test specific feature
devcontainer features test -f <feature-name> .

# Test against specific base image
devcontainer features test -f <feature-name> -i chainguard/wolfi-base:latest .

# Skip autogenerated tests, run only scenarios
devcontainer features test -f <feature-name> --skip-autogenerated --skip-duplicated .

# Test global scenarios only
devcontainer features test --global-scenarios-only .
```

### Validation
```bash
# Validate devcontainer-feature.json files
devcontainer validate --base-path-to-features ./src
```

### Development Environment
The project uses a Node.js-based development container with the DevContainer CLI pre-installed:
```bash
npm install -g @devcontainers/cli
```

## Architecture

### Feature Structure
Each feature is self-contained with:
1. **Metadata** (`devcontainer-feature.json`): Defines options, dependencies, and VS Code customizations
2. **Installation Script** (`install.sh`): Shell script that installs packages using `apk` (Alpine Package Keeper)
3. **Test Scenarios** (`scenarios.json`): Different configuration combinations for testing

### Key Features

**bash**: Installs Bash shell and adds it to `/etc/shells`

**python**: Installs Python (3.10-3.12) with optional Ruff linter and uv package manager

**user**: Creates non-root users with configurable UID/GID, essential for proper file permissions

**docker-outside-of-docker**: Provides Docker CLI access to host Docker daemon via socket mounting, includes optional Buildx and Compose

### Dependencies
- `docker-outside-of-docker` depends on the `user` feature
- All features use `apk` package manager (Wolfi/Alpine)
- Features are designed to work with `chainguard/wolfi-base:latest`

### Testing Strategy
- **Scenarios**: Test different feature option combinations
- **Autogenerated**: Basic installation tests
- **Global scenarios**: Cross-feature integration tests
- Uses `dev-container-features-test-lib` for test utilities

## Conventions

### Shell Scripts
- Use `#!/bin/sh` for maximum compatibility
- Always `set -e` for error handling
- Use environment variables with defaults: `VARIABLE=${ENVVAR:-"default"}`
- Check package installation status before installing
- Use `apk update` before package installation
- Provide informative echo statements for debugging

### Feature Options
- Use boolean options for optional components
- Provide sensible defaults
- Support version selection where applicable
- Use "automatic" for auto-detection scenarios

### Testing
- Each feature should have comprehensive test scenarios
- Test both positive and negative cases (e.g., verify optional tools are not installed when disabled)
- Use descriptive test names matching the scenario being tested
